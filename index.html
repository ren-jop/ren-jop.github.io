Working method

I use AI heavily, but it sits inside the engineering process. The point is to shorten the path between a question, a test and a better version.

Build against reality

I prefer a real build, physical prototype or playable interaction loop over speculative architecture. Compiler output, runtime behaviour and hardware documentation decide whether an idea survives.

Use AI to narrow the search

I use AI to inspect build errors, compare implementation options, synthesise technical documentation, generate debugging hypotheses and turn rough context into smaller next steps.

Keep context durable

AI also helps maintain handoffs, roadmaps, study material and structured notes so long-running projects can continue without reconstructing every decision from memory.

AI in the work

AI is integrated into Swift and Rust debugging, embedded-documentation synthesis, gameplay issue analysis, project planning, note organisation and study workflows.

Generated output is treated as a proposal. The source of truth is still the code that compiles, the documentation that describes the hardware, the behaviour I can reproduce and the interface that actually works.
