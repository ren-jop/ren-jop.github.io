A 2D cave-survival game I made while learning Rust and Bevy. Most of the work ended up being about making lots of small systems feel understandable together.

What I built

The game has movement, jumping, collisions, procedural caves, injuries, bleeding, fractures, hunger, thirst, crafting, enemies, hazards and an extraction objective.

Procedural generation

My first cave generator could create jumps that were impossible. I changed it so there is always a reachable route and then added randomness around that path instead of making the whole cave unconstrained.

Movement and feedback

I added coyote time and jump buffering because the first movement pass felt harsher than I wanted. The survival systems also taught me that adding state is easy; making the player understand why that state changed is harder.

Things I simplified

I originally had more inventory complexity, including a weight system. Testing showed it mostly made the game harder to read, so I removed it and kept the hotbar and crafting flow simpler.

Why I kept working on it

It gave me a very different way to learn Rust from Oxide Keys. Instead of registers and hardware constraints, I was dealing with ECS architecture, game feel, procedural generation and player-facing iteration.
