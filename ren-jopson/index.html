Working method

I use AI a lot, but it is a tool inside the process rather than the subject of the work.

Build against reality

I prefer a real build, physical prototype or playable interaction loop over a speculative architecture. Compiler output, runtime behaviour and hardware documentation decide whether an idea survives.

Use AI to narrow the search

I use AI to inspect build errors, compare implementation options, synthesise technical documentation, generate debugging hypotheses and turn rough project context into smaller next steps.

Keep context durable

For long-running projects I use AI to help maintain handoffs, roadmaps, study material and structured notes so work can continue without reconstructing every decision from memory.

AI in the work

AI is heavily integrated into my engineering and productivity workflow: Swift and Rust debugging, embedded-documentation synthesis, gameplay issue analysis, project planning, note organisation and study workflows.

I treat generated output as a proposal. The source of truth is still the code that compiles, the documentation that describes the hardware, the behaviour I can reproduce and the interface that actually works.
